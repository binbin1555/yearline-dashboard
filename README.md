# 年线轮动策略看板

创业板 + 中证红利年线轮动策略的每日监测与推送系统。

- **网页** 纯静态，托管在 GitHub Pages，浏览器端实时重算
- **推送** Bark，每个交易日 21:00（北京时间）
- **调度** cron-job.org 触发 GitHub Actions（不用 GitHub 自带 schedule，它会延迟或丢触发）
- **数据** 中证指数官网 / 雪球 / 新浪 / 腾讯，四源降级

新手请直接看 [部署指南.md](部署指南.md)。

## 一、策略规则（v1.0）

### 创业板腿 —— 信号取自 **创业板指 399006**

| | 条件 |
|---|---|
| 进场 | 收盘 > MA250 **且** 当日成交额 ≥ 前 20 日均额 × 1.3 |
| 出场 | 收盘 < MA250（无缓冲、无连续日确认） |
| 止盈 | 段内涨幅（自进场执行日收盘价算起）首次 ≥ 80% → 卖出一半，每段只触发一次 |

> **信号取自创业板指 399006，实际持仓是创业板50。** 这是刻意选择：两者日收益相关系数 0.9915、beta 1.059，用慢信号驱动高弹性标的。页面与推送的盈亏一律按**创业板50 的真实涨跌**计算。

### 红利腿 —— 信号取自 **中证红利 000922**

- 平时空仓（货基／逆回购，按 1.5%/年计息）
- 跌破自身 MA250 的 **−4% / −7% / −10%** 三档，每档买 1/3 仓
- 涨回 MA250 → 三档一次性全清，回到空仓
- 一轮内每档只买一次（档位只增不减，止盈时重置）

### 优先级与执行

1. 创业板进场信号优先级最高，触发时无条件清掉红利仓位
2. 出场信号优先于止盈
3. 从创业板出场时，**立即**按当前位置补齐已触发档位
4. 止盈卖出的那一半进入防守腿后**立刻参与网格**，不等创业板腿出场
5. 信号按收盘价判定，**T+1 收盘执行**

## 二、配置项 `config.json`

| 字段 | 说明 |
|---|---|
| `start_date` | **推送**使用的起算日。改成你实际开始执行策略的那天 |
| `initial_capital` | 推送使用的本金 |
| `page_url` | Bark 推送的点击跳转地址。留空则推送不带链接 |
| `lookback_days` | 每次抓取回溯的自然日数，用于补齐遗漏和修订 |
| `alert_stale_days` | 数据停滞超过这么多天就告警（默认 10，够覆盖春节／国庆长假） |
| `final_after_hour` | 早于这个钟点（北京时间）抓到的当日数据视为盘中实时值，丢弃 |

> **网页底部也能改初始资金和启动时间，但那只存在浏览器 localStorage 里，只影响网页显示，不影响推送。**
> 想让推送口径也变，改 `config.json` 并提交。

## 三、数据与容错

### 数据源优先级

| 序列 | 主源 | 备源 |
|---|---|---|
| 创业板指收盘 | 雪球 | 新浪 → 腾讯 |
| 创业板指**成交额** | 雪球 | **无**（只有雪球提供指数成交额） |
| 创业板50 收盘 | 雪球 | 腾讯 |
| 中证红利收盘 | 中证指数官网 | 雪球 → 新浪 |
| 中证红利全收益 | 中证指数官网 | **无** |

### 三条硬规则

1. **宁可不更新，绝不用陈旧数据冒充新数据。** 某个交易日只有在五个序列**全部**拿到时才写入，缺一个就整天跳过。
2. **盘中数据一律丢弃。** 早于 `final_after_hour`（默认 17:00 北京时间）抓到的当日数据是实时值不是收盘价，直接扔掉。正常 21:00 触发不受影响。
3. **仓库预置全历史。** GitHub runner 在美国，中国金融接口可能限流。即使某天全部抓不到，页面依然完整可用，只是数据截止日不前进并触发告警。

### 告警

| 情况 | 行为 |
|---|---|
| 所有数据源不可达 | Bark 告警（**任何时候都推，不静默**） |
| 数据停滞超过 `alert_stale_days` | Bark 告警 |
| 策略引擎报错 | Bark 告警 |
| 非交易日且一切正常 | 静默 |
| 交易日 | 推送当日概况；有待执行操作时用 `timeSensitive` 级别 |

## 四、目录

```
├── .github/workflows/update.yml   每日更新工作流
├── scripts/
│   ├── fetch.py                   多源降级抓取 + 合并
│   ├── strategy.py                策略引擎（Python）
│   └── run.py                     主流程 + Bark 推送
├── data/
│   ├── daily.json                 全历史日线（种子 + 每日增量）
│   └── status.json                最新状态快照
├── index.html / style.css / app.js  网页（浏览器端重算）
├── config.json
└── 部署指南.md                     零基础部署步骤
```

**`scripts/strategy.py` 与 `app.js` 必须逐行等价**——页面显示与 Bark 推送同源同算。改动其中一个，另一个必须同步改，否则两边会给出不同的操作建议。

已验证：两个引擎在起点 2015-06-24 / 2019-01-02 / 2024-01-02 三组参数下，净值、年化、最大回撤、事件数逐位相同。

## 五、数据校验记录

| 数据 | 校验 |
|---|---|
| 399006 收盘 | 雪球 vs 新浪 3930 天，仅 1 天偏差 >0.5 点（0.027%） |
| 399006 成交额 | 全历史零缺失 |
| 000922 收盘 | 雪球 vs 中证指数官网 5244 天，**0 天偏差** |
| 年度收益外部验证 | 回测算出的创业板指年度涨跌与官方公布值逐年精确吻合（2013 +82.73%、2015 +84.41%、2016 −27.71%、2018 −28.65%、2019 +43.79%、2020 +64.96%、2021 +12.02%、2022 −29.37%、2023 −19.41%、2024 +13.23%） |

**已知环境坑**

- 东方财富接口在部分网络环境完全不可达，已不使用
- 雪球时间戳必须按 **UTC+8** 显式换算。CI 跑在 UTC、开发机可能在别的时区，用 `localtime` 会让日期整体错位一天
- Windows 上必须有 `.gitattributes` 强制 LF，否则 Actions 在 Ubuntu 上会因 CRLF 报 `$'\r': command not found`
